# 1CHarness — инструкции для агентов

## После правок — проверять, что всё работает

Перед завершением задачи (коммит, PR, ответ пользователю) **обязательно** прогнать проверку и убедиться, что затронутый функционал жив.

1. **Автоматически:** из корня репозитория  
   `bash scripts/verify_harness.sh`  
   (stub 1С, `workspace/config.json`, при наличии `OLLAMA_API_KEY` — короткий запрос к LLM).

2. **UI / агент в браузере** (если менялись `index.html`, `web/js/*`, темы, чат):  
   - `python3 scripts/harness_dev.py` (статика + same-origin `/dev-llm/*` для обхода CORS в браузере);  
   - открыть `http://127.0.0.1:<port>/index.html`;  
   - **Enter** (без Ctrl) отправляет сообщение; ответ модели появляется в диалоге.  
   - опционально: `node scripts/browser_smoke_chat.mjs` (нужен `npm install playwright` в корне).

3. **EPF / 1С** (если менялись `src/1CHarness/`):  
   навыки **epf-build** / **epf-dump** (cc-1c-skills), без shell-обёрток в репо.

4. **Итог пользователю:** кратко написать, *что* проверили и *результат* (OK / что сломалось и как чинили). Не сдавать «вслепую» без хотя бы `verify_harness.sh` для затронутого JS/агента.

Не считать задачу выполненной, если проверка не запускалась или упала без исправления.

## Архитектура (кратко)

- LLM — прямой XHR, настройки в `workspace/config.json` через мост 1С.
- Сессии — `workspace/sessions/*.json`, агенты — `workspace/agents/*.md`.
- В dev платформу имитирует `web/js/stub-1c-platform.js`; без отдельного Python HTTP-моста для чата.

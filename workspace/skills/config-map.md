# Карта данных конфигурации (`data/map.md`)

Карта — **не** полная выгрузка метаданных. В Markdown фиксируются темы (деньги, склад, долги, продажи…), **используемые** объекты, подсказки к запросам и таблица **flows** (что на что влияет).

Субагент `explore_data` читает карту из `data/map.md`. Без карты или при другом `configurationName` в новом диалоге пользователю предлагают построить карту (кнопки «Да» / «Нет»).

## Файл и frontmatter

Путь: **`data/map.md`**. В начале — YAML frontmatter между `---`:

```markdown
---
version: 1
configurationName: УправлениеНебольшойФирмойУчебная
configurationSynonym: Управление нашей фирмой (учебная)
updatedAt: 2026-10-29
---
```

- `configurationName` — строго `session_now.configurationName` текущего сеанса.
- `version` — всегда `1` в этой версии формата.

## Разделы тела документа

1. **`## Topics`** — подзаголовки `### <id> — <подпись>`, списки `- objects:` или `- note:` (если учёт не ведётся).
2. **`## Objects`** — подзаголовок `### ПолноеИмяОбъекта`, булево `- used: yes|no`, `- topics:`, `- query:` / `- report_run:`.
3. **`## Flows`** — таблица Markdown: From | To | On | Effect.

Объект с `used: no` оставляют в карте, чтобы не искать его снова.

## Алгоритм сборки (субагент)

1. `session_now` → записать `configurationName` / `configurationSynonym` в frontmatter.
2. Темы: money, inventory, sales, receivables, payables, prices, nomenclature — для каждой найти регистры через `inspect_metadata` (типовые имена УНФ) или `- note: не найден`.
3. Для каждого найденного объекта — `inspect_metadata`, кратко `- query:` с виртуальной таблицей (`.Остатки`, `.Обороты`, `.СрезПоследних`).
4. Проверка: `run_query` с `ПЕРВЫЕ 1` или `limit: 1`; при ошибке не включать объект как `used: yes`.
5. **Flows** — документы, которые пишут регистры при проведении (из метаданных и смысла конфигурации).
6. **`fs_write`** path `data/map.md` — **полный** Markdown (frontmatter + тело), UTF-8, без JSON.

## Ограничения

- Не включай в карту все объекты конфигурации — только нужные агенту.
- Не выдумывай имена регистров: только после успешного `inspect_metadata` или `run_query`.
- После записи файла кратко сообщи, сколько объектов с `used: yes` и какие темы закрыты.

# Карта данных конфигурации (`data/map.json`)

Карта — **не** полная выгрузка метаданных. В ней только объекты, которые нужны агенту, темы (деньги, склад, долги, продажи…), подсказки к запросам и **связи** «документ → регистр при проведении».

Субагент `explore_data` получает карту при старте (если файл есть и имя конфигурации совпало). Без карты он ищет объекты вслепую — дольше и чаще ошибается.

## Когда обновлять

- Подключили другую базу (другое `configuration.name`).
- Добавили в конфигурацию новые регистры, с которыми работает агент.
- Субагент несколько раз ошибся «таблица не найдена» — допишите объект или пометьте `"used": false`.

## Формат (version 1)

Файл: `data/map.json`.

| Поле | Назначение |
|------|------------|
| `configuration.name` | `Метаданные.Имя` сеанса (см. `session_now.configurationName`) |
| `configuration.synonym` | Для людей, необязательно |
| `topics` | Темы запроса → список `fullName` или пояснение, что в базе не ведётся |
| `objects[]` | Объекты с `used`, `topics`, `queryHints` |
| `flows[]` | `from`, `to`, `on`, `effect` — что на что влияет |

Объект с `"used": false` в карте остаётся (чтобы не искать снова), но субагент не должен строить запросы к нему без явной задачи.

## Как построить карту (пошагово)

1. **Имя конфигурации** — `session_now`, поле `configurationName`. Запишите в `configuration.name`.
2. **Темы задачи** — выпишите, что пользователи спрашивают: деньги, товары, долги нам/наши, продажи, цены, номенклатура.
3. **Поиск регистров** — для каждой темы:
   - `inspect_metadata` по типовым именам УНФ/ERP (`ДенежныеСредства`, `ТоварыНаСкладах`, `РасчетыСПокупателями`, `Продажи`, …);
   - если объекта нет — зафиксируйте в `topics.<тема>.description`, не выдумывайте имя.
4. **Документы** — для документов отгрузки/оплаты: `inspect_metadata`, табличные части, `registerRecords` (если видно в метаданных) или проведите один тестовый документ в копии базы и посмотрите движения.
5. **flows** — для каждой пары документ→регистр: `{ "from": "Документ.…", "to": "Регистр….", "on": "Проведение", "effect": "…" }`.
6. **queryHints** — рабочие виртуальные таблицы: `.Остатки`, `.Обороты`, `.СрезПоследних`, имена полей оборотов (`СуммаОборот`, `КоличествоОборот`).
7. **Проверка** — один `run_query` на объект с `LIMIT`/«ПЕРВЫЕ 1», убедитесь что запрос выполняется.
8. **Сохранение** — `fs_write` path `data/map.json`, UTF-8, `JSON.stringify(..., null, 2)`.

## Пример фрагмента для УНФ (учебная)

Имена уточняйте через `inspect_metadata` в **вашей** копии базы:

```json
{
  "topics": {
    "money": {
      "label": "Деньги",
      "objects": ["РегистрНакопления.ДенежныеСредства"]
    },
    "inventory": {
      "label": "Товары",
      "objects": ["РегистрНакопления.ТоварыНаСкладах"]
    },
    "receivables": {
      "label": "Долги покупателей",
      "objects": ["РегистрНакопления.РасчетыСПокупателями"]
    }
  }
}
```

## Связь с `explore_data`

Субагент сначала смотрит `topics` и `objects` по задаче, затем `flows` (откуда берутся движения), и только потом перебирает `inspect_metadata` вне карты.

Главный агент может поручить обновление карты: «построй карту по навыку config-map» → `find_skill` → серия `inspect_metadata` / `run_query` → `fs_write data/map.json`.
